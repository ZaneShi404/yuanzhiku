# ADR-011：视频直送补充理解与双供应商适配

状态：接受（v1.5，2026-08-16 用户裁定修订）。

完整性判断为「可能缺失」后的补充理解改为两级（取代 ADR-006 的 tier2 关键帧
路径，用户裁定 2026-08-16）：① 视频直送——`ai_video_provider`（off/qwen/mimo）
非 off 时把视频文件直送多模态模型（通义千问 DashScope 临时上传 + video_url；
小米 MiMo OpenAI 兼容 `api.xiaomimimo.com/v1` + `mimo-v2.5` base64 传入），由
多模态模型**一次性产出**三部分（偏差 A 用户裁定）：补充转写/画面理解（带时间
定位）+ 200-600 字摘要 + 建议分类（强制收敛到分类体系）；转写文本始终随附；
分块直送时逐段产出理解条目、最终由同一多模态模型以纯文本调用合成摘要；② 直送
不可行（未配置、超 min(设置 300MB, 供应商能力) 上限、调用失败）时，摘要仍由
纯文本模型按 tier1 产出并标记 visual_gap（关键帧视觉路径已彻底移除，偏差 B
用户裁定）。MiMo 无本地文件上传接口（官方 FAQ 核实），公网 URL 路径不适用于
本地视频——超限视频经显式重编码（`ai_video_reencode`，低码率视频 + ≥48kbps
音轨，显式开关+摘要标记+审计，非静默降质）、仍超限按 `ai_video_chunk_seconds`
（默认 600s）分块直送（每段完整发送、段偏移合并、段级跳过并注明，与音频分块
转写同一模式）。用户自备视频中转（决策 22）有两种形态：http（`tools/video-relay/` 部署物，需已备案域名）与 cos（腾讯云对象存储，`RelayClient` 内建，未备案环境下的默认路径——COS 默认域名自带有效 HTTPS 证书、上传走 COS API、拉取后按 cleanup 删除对象）；
配置后两适配器优先经 relay URL 直送（MiMo 吃满 300MB URL 上限、Qwen 免临时
上传流程）；应用不管理中转生命周期，中转地址/密钥受 REQ-052 统一校验与凭据
纪律。所有直送字节仅发往用户显式配置端点，API 原始响应不落库不落日志；输出
按 `video_time_range` 证据落库。后果：缺失内容补充由「视频本体理解」一步完成
（转写、理解、摘要三部分均出自多模态 API，符合用户设想），成本仅在判定触发时
发生；两级回退保证任何情况下不空手、不伪造。（`REQ-055`、`REQ-051`/`REQ-052`
修订、`REQ-033a`）
