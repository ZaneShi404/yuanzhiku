# ADR-011：视频直送补充理解与双供应商适配

状态：接受（v1.5）。

完整性判断为「可能缺失」后的补充理解从「关键帧 → 视觉模型」单层扩展为三级
（决策 16/17/20/21/22）：① 视频直送——`ai_video_provider`（off/qwen/mimo）非
off 时把视频文件直送多模态模型（通义千问 DashScope 临时上传 + video_url；小米
MiMo OpenAI 兼容 `api.xiaomimimo.com/v1` + `mimo-v2.5` base64 传入），模型支持
音频理解时一并做补充转写，纯视觉模型随视频附带已有转写文本做画面定位；② 直送
不可行（未配置、超 min(设置 300MB, 供应商能力) 上限、调用失败）时兜底为现有
关键帧画面理解；③ 均不可用时标记 visual_gap。MiMo 无本地文件上传接口（官方 FAQ
核实），公网 URL 路径不适用于本地视频——超限视频经显式重编码（`ai_video_reencode`
，低码率视频 + ≥48kbps 音轨，显式开关+摘要标记+审计，非静默降质）、仍超限按
`ai_video_chunk_seconds`（默认 600s）分块直送（每段完整发送、段偏移合并、段级
兜底，与音频分块转写同一模式）。用户自备云服务器中转（决策 22，`tools/video-relay/`
部署物）配置后两适配器优先经 relay URL 直送（MiMo 吃满 300MB URL 上限、Qwen 免
临时上传流程）；应用不管理中转生命周期，中转地址/密钥受 REQ-052 统一校验与凭据
纪律。所有直送字节仅发往用户显式配置端点，API 原始响应不落库不落日志；输出按
`video_time_range` 证据落库。后果：缺失内容补充从「画面抽样」升级为「视频本体
理解」，成本仅在判定触发时发生；三级回退保证任何情况下不空手、不伪造。
（`REQ-055`、`REQ-051`/`REQ-052` 修订、`REQ-033a`）
