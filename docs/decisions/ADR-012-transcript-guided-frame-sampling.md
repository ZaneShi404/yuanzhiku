# ADR-012：转写引导的关键帧采样与管线重排

状态：接受（v1.7，2026-09-04 用户审定）。

视频管线重排为「转写先行」（取代 v1.4.1 以来的「分析 → 转写 → 摘要」线性链，
`REQ-056`、决策 23/24）：入库单事务按入队矩阵同队 `video_transcribe`（priority
110）与 `video_analyze`（100）——`ai_auto_pipeline=on` 且任一转写路径可用时双
入队，priority 差加单 worker 串行保证转写先执行；矩阵未命中（auto off 或转写
器不可用）仅入队分析，保持 v1.6 语义。分析作业读取同版本 transcription 表示做
锚点融合：抽帧锚点池 = 场景切变点（scene>0.3）∪ 转写段边界 ∪ 静音空档中点
（≥2s 空档）∪ 等间隔锚点，槽位吸附优先级 scene > transcript/silence > even，
帧 reason 扩展 transcript/silence（自由 TEXT 列，零 schema 迁移）；无转写表示
时自动退化为纯信号抽帧（行为与 v1.6 逐位一致），分析作业全程零网络不变。
分析身份 `config_hash` 纳入转写来源（transcription 表示的 config_hash；无转写
时与 v1.6 原值一致可幂等复用）——转写晚到或换引擎后的重分析构成新分析身份并
存（detail 取最新），绝不与旧身份共享帧集；转写晚到后经新增
`POST /videos/{id}/analyze` 手动重分析获得引导帧。分析成功仍是来源 ready 的
唯一写点（`REQ-033a`）；转写晚配置场景由分析成功时补链转写（无转写表示且转写
器可用时）兜底，转写成功链式摘要不变。后果：口播/讲座类视频（镜头不切、场景
检测退化等间隔）的抽帧获得语义锚点；代价是来源 ready 与详情页帧的出现时间推
迟到转写之后（前端已验证安全降级）。已知边界：转写里没有线索的时刻锚点也提
不出——「语音里没有的画面信息」由 ADR-013 的画面理解路径兜底，两条腿互补。
（`REQ-056`、`REQ-016`/`REQ-051`/`REQ-053` 修订）
